# 登录首屏翻新设计规格

**日期：** 2026-08-06  
**状态：** 用户已授权按推荐方向直接推进  
**范围：** 未登录公开首页首屏（导航、品牌主张、能力预览、登录/注册卡片）

## 目标

将当前信息较多、认证卡片偏拥挤的首屏，翻新为可信、清晰、有申请业务辨识度的进入界面。新首屏应让学生和家长在几秒内理解三件事：这是美本申请工作台、登录后可以继续管理真实申请资料、AI 输出需要结合证据和人工核验。

本次只调整未登录首屏的结构、文案和视觉表现。下方公开介绍模块、登录后的工作台、认证接口、数据库、密码重置流程和业务数据均不重构。

## 设计方向

采用“申请档案台（Admissions Desk）”方向。

页面不使用通用 AI 产品常见的霓虹渐变、悬浮光球或虚构数据，而借用申请材料、档案标签、审核路径和决策记录的视觉语汇。整体保持现有品牌的暖白底色、深色文字、绿色可信语义和橙色主行动，但提高对比度并减少装饰。

### 设计令牌

- `Compass Ink #10243A`：主标题、重要信息和深色结构线。
- `Archive Paper #F5F3EC`：首屏底色，接近申请资料纸张而不是纯白画布。
- `Decision White #FFFFFF`：认证卡片和关键内容表面。
- `Evidence Green #246B4B`：可信资料、已核验和品牌识别。
- `Action Amber #D97716`：注册、登录等唯一主行动。
- `Reference Blue #DCEAF4`：路径图中的资料与院校参考层。

字体继续使用当前系统字体栈，避免新增外部字体请求；通过标题字宽、行高、标签字距和数字样式建立层级。主标题更紧凑，正文保持高可读性，路径标签采用较小的工具型排版。

## 首屏结构

### 桌面布局

首屏采用顶部品牌栏加 60/40 双栏 Hero：

```text
┌──────────────────────────────────────────────────────────────┐
│ US College Compass             规划方式  登录后能力  风险边界 │
├───────────────────────────────────┬──────────────────────────┤
│ FREE APPLICATION WORKSPACE        │ 登录 / 注册工作区        │
│ 从散落信息，                      │ 标题与简短说明            │
│ 到有依据的申请决策                │ 姓名（注册时）            │
│                                   │ 邮箱                      │
│ 一句产品说明          [开始按钮]  │ 密码                      │
│                                   │ [主提交按钮]              │
│ Profile ─ Evidence ─ Decisions    │ 找回密码 / 切换模式       │
│ 学生档案   能力证据    选校与行动  │ 安全与数据边界提示        │
└───────────────────────────────────┴──────────────────────────┘
```

左侧由品牌主张、说明、主行动和“Compass 路径线”组成。路径线将真实能力分为三个有因果关系的阶段：

1. `Profile`：成绩、课程、活动与个人方向。
2. `Evidence`：能力评估、资源与院校资料核验。
3. `Decisions`：选校轮次、规划版本和下一步行动。

路径线是首屏唯一明显的视觉签名。它应看起来像一条申请资料从录入到决策的工作流，而不是三个无关联的营销数字。

右侧认证卡片只保留认证所需信息。现有卡片内的行动地图预览和三个报告小块迁移到左侧路径区域，降低表单前的阅读负担。卡片底部提供短句说明：账号用于保存规划、档案和进度；详细边界链接到免责声明。

### 移动布局

在约 390px 宽度下，顺序为品牌栏、核心标题与短说明、认证卡片、压缩后的三阶段路径。主行动按钮不额外重复，避免与表单提交按钮竞争。导航折叠为必要入口或允许横向紧凑排列，页面不得横向溢出。

认证卡片必须在首屏主要内容之后立即出现；路径预览可后置，确保用户无需长距离滚动即可登录。

## 认证状态

保留当前三种状态和所有关键元素 `id`：

- 注册：显示姓名、邮箱、密码，主按钮明确表示创建账户并开始规划。
- 登录：隐藏姓名，标题和按钮显示“登录”，保留注册链接。
- 找回密码：使用邮箱发送重置请求，保留当前状态提示和安全反馈。

保留原生表单 `method="post"`、服务端根据 `?auth=login` 生成登录状态的能力、`aria-live` 状态区域、键盘焦点和请求期间禁用状态。登录失败、重复注册、限流或重置请求的错误处理逻辑不修改。

## 文案原则

- 不使用“保录”“精准预测”或无来源的成功率。
- 不继续强调“全免费”作为首要品牌信息；可以客观说明当前核心功能可使用。
- 用“申请工作区”“证据”“核验”“下一步行动”等用户可理解的业务词汇。
- 主标题为“从散落信息，到有依据的申请决策”。
- 副文案说明档案、规划、选校和 AI 辅助能力，但明确最终信息需要核验。

## 文件与实现边界

预计修改：

- `index.html`：重组 `authShell` 首屏内部结构，保留认证与下方公开模块的关键 `id`。
- `styles.css`：在文件末尾增加作用域明确的首屏样式，避免继续修改多处历史重复规则。
- `src/client/app.js`：仅在文案或聚焦行为确有需要时进行最小调整，不重写认证请求。
- `tests/planning-workspace-layout.test.mjs`：更新首屏结构和文案断言。
- 必要时增加一个聚焦首屏结构的测试文件，避免把更多断言堆入已有大测试。

明确不修改：

- `server.mjs` 和任何认证、数据库、隐私守卫模块。
- API 路径、Cookie、CSRF、密码与会话逻辑。
- 登录后的工作台结构和业务功能。
- 下方公开介绍模块的内容顺序，除非首屏锚点需要最小同步。

## 可访问性与动效

- 所有输入继续使用可见标签，不以占位符替代标签。
- 键盘焦点必须具有高对比轮廓。
- 状态消息继续使用 `role="status"` 和 `aria-live="polite"`。
- 路径线可使用一次轻量进入动画，但在 `prefers-reduced-motion: reduce` 下关闭。
- 颜色不作为阶段和错误状态的唯一识别方式，阶段始终有文字标签。

## 验收标准

1. 1280px 桌面视口下首屏形成明确的 60/40 双栏，认证卡片完整可见且没有内容重叠。
2. 390px 手机视口下标题、表单和切换入口均不横向溢出，认证卡片在路径预览之前。
3. 注册、登录、找回密码、重置完成、退出后返回等状态继续工作。
4. `authForm`、`authNameField`、`authEmail`、`authPassword`、`authStatus`、`authSubmitButton`、`forgotPasswordButton` 和 `authModeButton` 均保留。
5. `?auth=login` 在 JavaScript 执行前仍呈现正确的登录标题、表单 action、隐藏姓名字段和注册链接。
6. 不新增第三方字体、远程图片、追踪脚本或无事实依据的数据。
7. `npm run verify` 通过；若既有 RAG 绝对延迟门槛仍受环境影响，单独如实记录。
8. 使用浏览器在桌面与移动宽度完成视觉和交互冒烟检查。

## 自审结论

- 无 `TBD`、`TODO` 或未决视觉选择。
- 范围限定为未登录首屏，不扩展到登录后工作台或后端认证。
- 视觉签名、响应式顺序、状态保护和测试要求之间无冲突。
- 用户已明确选择整个未登录首屏，并授权后续设计与实现无需再次确认。
