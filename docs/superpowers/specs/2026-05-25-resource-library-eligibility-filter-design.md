# 资源库资格与参与方式筛选设计

## 目标

在“资源库”页面新增一次性使用的可参与条件筛选，帮助学生在浏览竞赛库和夏校库时识别哪些项目可继续关注、哪些项目因明确资格或参加方式冲突而应排除。

本功能的原则是“保守判断、透明提示”：仅在资源资料与用户条件能够明确判定冲突时排除项目；信息不足时保留项目并提示核实，避免错失可申请机会。

## 功能边界

本次功能仅应用于 `resource-library.html` 资源库页面。

包含：

- 用户临时填写国籍与身份说明。
- 用户选择可接受的参加方式。
- 竞赛库与夏校库根据这些条件展示可查看项目和已排除项目。
- 信息不充分时展示待核实状态。

不包含：

- 不改变 Agent 当前生成的竞赛推荐或夏校推荐。
- 不把筛选条件写入账号资料、数据库或浏览器持久存储。
- 不自动判断签证、旅行许可、费用或截止日期是否满足。
- 不将手动身份文字视为可靠的法律资格证明。

## 用户输入

资源库页面顶部新增“我的可参与条件”区域，包含三个输入项：

- `国籍`：自由文本输入，例如“中国”。
- `身份说明`：自由文本输入，例如“中国大陆高中在读，无美国公民或绿卡身份”。
- `参加方式`：单选项，分别为`仅线上`、`仅线下`、`线上线下都可`。

这些输入只保存在当前页面内存状态中。刷新页面、关闭页面或重新进入页面后不会恢复。

页面提供`应用筛选`与`清除条件`操作。未填写条件时，资源库维持当前的全量浏览体验。

## 资源数据补充

每个竞赛或夏校资源应能提供用于筛选的结构化状态：

- `participationMode`：`online`、`offline`、`hybrid` 或 `unknown`。
- `eligibilityStatus`：`open_to_international`、`us_status_only`、`restricted` 或 `unknown`。
- `eligibilityNote`：面向用户显示的资格说明文本，例如“仅美国公民或永久居民可申请”。

首版不要求立刻为全部历史数据做人工精标。尚未补充可靠字段的资源统一视作`unknown`，仍可浏览并提示用户核实。

## 判断规则

### 参加方式

- 用户选择`仅线上`时，明确为`offline`的项目进入已排除项目。
- 用户选择`仅线下`时，明确为`online`的项目进入已排除项目。
- 用户选择`线上线下都可`时，不因参加方式排除任何项目。
- `hybrid`项目对三种选择均可保留。
- `unknown`项目始终保留，并显示`参与方式待核实`。

### 国籍与身份

- 页面仅依据资源中明确的身份资格限制进行判断。
- 用户输入国籍和身份说明后，资源明确标记为`us_status_only`，且用户文字明确声明不具备美国公民或永久居民身份时，该资源进入已排除项目。
- 如果用户的文字没有形成明确冲突，资源继续显示，并可标注`资格待核实`。
- `open_to_international`项目不因用户填写国际学生身份而排除。
- `restricted`与`unknown`项目默认保留，并显示资格说明或`资格待核实`提示。

此规则刻意避免根据模糊关键词推断身份，减少误排除风险。

## 页面展示

页面保留现有`竞赛库`与`夏校库`切换及关键词搜索，并在当前分类中应用同一组临时筛选条件。

应用条件后，每个分类显示两组内容：

- `可查看项目`：没有明确冲突的项目。资源卡显示参与方式、身份资格与可能的待核实标签。
- `已排除项目`：明确不符合条件的项目。资源卡至少显示项目名称和排除原因，例如“仅限美国公民或永久居民”或“仅提供线下参与，与仅线上条件冲突”。

页面应显示数量概览，例如可查看数量和已排除数量，便于用户理解筛选结果。

## 模块边界

为保持页面脚本清晰，筛选判断应从 DOM 渲染中分离：

- 筛选规则模块负责接收资源条目与用户条件，输出`included`、`excluded`以及提示/排除原因。
- `resource-library.js`负责读取表单状态、调用筛选规则、执行搜索与渲染结果。
- `resource-library.html`与`styles.css`负责筛选控件、标签、已排除区域和响应式布局。

这一拆分使资格规则可以单独测试，也方便后续人工补充更精准的资源标签。

## 异常与空状态

- 未输入任何条件时，不显示误导性的资格结论，正常展示现有资源。
- 条件已应用但没有项目可查看时，显示清晰空状态，并保留已排除原因列表。
- 资源字段未知时，不将项目判为不合格，只展示待核实提示。
- 数据加载失败时，沿用资源库现有错误状态，不展示基于不完整加载的筛选结果。

## 测试与验收

实现后至少验证：

- `仅线上`排除明确线下项目，保留线上、混合与未知项目。
- `仅线下`排除明确线上项目，保留线下、混合与未知项目。
- `线上线下都可`不因方式排除项目。
- 用户明确说明无美国身份时，`us_status_only`资源进入已排除项目并显示原因。
- 资格或参与方式未知的资源保留，并展示待核实标签。
- 清除条件后恢复全量列表。
- 关键词搜索与分类切换可和筛选条件共同工作。
- 登录保护与已有资源加载流程不受影响。

## 后续扩展

后续若用户需要，结构化资格字段可升级为由管理员维护的资源标注流程，或进一步加入年级、年龄、预算、日期与地区可达性筛选。本次不预先实现这些范围。
