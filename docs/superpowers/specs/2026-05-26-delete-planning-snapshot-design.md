# 删除历史备份设计规格

**日期：** 2026-05-26  
**状态：** 已确认交互方案，待实施计划  
**范围：** 申请规划首页的历史备份列表与对应服务接口

## 目标

允许登录用户从当前规划方案的“历史备份”列表中删除不再需要的单条备份，同时避免误删和避免影响当前正在编辑的方案内容。

## 交互设计

- 每条历史备份现有的“恢复”按钮继续保留。
- 在同一行增加“删除”按钮，并采用危险操作视觉样式。
- 点击“删除”后显示确认提示，说明删除的是这份历史备份且操作不可撤销。
- 用户取消确认时不发起删除请求，也不改变列表。
- 用户确认并删除成功后，立即重新载入当前方案的备份列表，并显示“备份已删除”的状态反馈。
- 删除最后一条备份后，列表恢复为现有的“还没有备份。”空状态。

## 数据与安全边界

- 删除操作只作用于指定 `snapshotId`，且必须同时属于当前登录用户与当前 `planId`。
- 删除备份不修改当前方案草稿、不修改学生资料、不触发备份恢复。
- 用户不能删除其他用户或其他方案下的备份；此类请求返回未找到。
- 删除不存在的备份返回未找到，不向用户暴露其他账户的记录信息。

## 实现范围

- `planning-service.mjs` 增加按用户、方案与备份 id 删除单条备份的方法。
- `server.mjs` 增加 `DELETE /api/plans/:planId/snapshots/:snapshotId` 路由。
- `app.js` 在备份行渲染删除按钮，增加确认及请求后刷新列表的客户端行为。
- `styles.css` 仅在现有布局不足以容纳双按钮时补充备份行按钮容器样式；沿用当前危险按钮样式。
- 现有创建与恢复接口、方案删除行为、导出行为均不改变。

## 测试与验收

- 服务测试覆盖删除属于当前用户当前方案的备份，且删除后该备份不再列出。
- 服务测试覆盖尝试删除其他方案或其他用户的备份时返回未找到。
- 接口测试覆盖 `DELETE` 成功与已删除记录再次删除的 `404` 响应。
- 页面结构测试覆盖备份列表提供删除动作标记。
- 浏览器验收覆盖创建备份后删除、确认提示、删除后列表刷新，以及当前方案内容不被覆盖。

## 不包含的内容

- 不提供批量选择、批量删除或撤销删除。
- 不增加回收站、备份重命名或备份下载功能。
- 不修改方案整体删除时一并清理备份的现有行为。
