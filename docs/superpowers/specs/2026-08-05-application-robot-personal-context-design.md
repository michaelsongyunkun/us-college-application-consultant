# 申请机器人个人上下文与知识 RAG 分离设计

## 目标

申请机器人不再默认把申请规划中心内容作为 RAG 知识源。外部知识检索与用户个人资料使用必须在数据流、界面说明和测试中保持清晰分离。

## 产品行为

- 普通自由提问默认关闭“参考我的申请规划”。
- 页面在提问区域提供明确的个人上下文开关，用户可以随时开启或关闭。
- “申请档案体检、选校策略分析、活动补强方案、推荐信策略、项目/竞赛/夏校匹配、院校匹配与差距分析、成绩与课程规划诊断、申请材料清单”等依赖个人资料的快捷任务，点击后自动开启该开关并按现有行为立即提交。
- 快捷任务区域必须明确披露这些任务会参考个人上下文；自动开启后的状态必须在页面上可见，并延续到后续追问，直至用户主动关闭或清空对话。
- 启发性机器人继续使用纯对话模式，不显示或提交该开关。

## 数据边界

### 知识 RAG

知识 RAG 始终可以检索以下非个人资料：

- 资源库；
- 院校百科；
- 专业百科；
- 基于上述资料构建的招生知识图谱。

### 个人上下文

只有请求中的 `usePersonalContext` 严格为 `true` 时，服务端才能读取：

- 当前学生画像；
- “我的申请档案”中的当前申请轮次、活动、竞赛、夏校、推荐信和学术记录；
- 申请规划中心最近更新的一份当前规划；按 `updated_at DESC, id DESC` 确定唯一结果。

服务端不得为申请机器人读取或发送：

- 任何历史规划快照；
- 最近更新规划以外的其他规划版本；
- 与个人上下文关闭状态不相符的个人资料或缺失字段提示。

## 架构与数据流

1. `ask-deepseek.html` 提供个人上下文开关。
2. `src/client/ask-deepseek.js` 将开关状态作为布尔字段 `usePersonalContext` 加入 RAG 请求。普通问题默认发送 `false`；依赖个人资料的快捷任务在即时提交前将其设为 `true`。
3. `server.mjs` 将该字段传入同步 RAG、后台任务和持久化任务边界。后台任务载荷只记录开关，不预先嵌入个人资料正文。
4. `src/server/deepseek-rag-service.mjs` 将个人上下文状态传入 LangGraph 和检索编排器。
5. 文档检索器始终加载静态知识文档；只有开关开启时才加载个人上下文文档。
6. `src/server/planning-service.mjs` 提供只返回最近更新当前规划的窄接口。原有快照功能保留给规划中心，但不再供申请机器人调用。
7. 知识图谱适配器在开关关闭时不得隐式调用 planning 或 activity portfolio 服务。开启时可以用当前画像和当前申请档案作为图谱查询证据。

## 检索与提示词行为

- 个人上下文关闭时，检索结果不得包含 `student-backup` 或 `application-portfolio` 类型来源。
- 个人上下文开启时，个人来源可以参与相关性排序，但不得再通过无条件基线注入历史规划。
- 当前画像、当前申请档案和最近规划属于 `personalContext`，不是外部知识库。响应来源增加 `scope: "personal" | "knowledge"`；个人证据保留现有内部类型用于排序，但界面统一标为“个人上下文”。
- 缺失字段检查只在个人上下文开启时执行。
- 系统提示词必须明确：只有请求提供个人上下文时才能据此个性化；没有提供时不得假设已读取用户档案。

## 界面文案

- 开关标签：`参考我的申请规划`。
- 辅助说明：`开启后会读取当前画像、申请档案和最近更新的一份规划；不会读取历史快照。`
- 页面数据范围说明改为区分“知识资料”和“可选个人上下文”，不再暗示规划版本默认进入 RAG。
- 等待状态根据开关显示：关闭时只说明检索参考资料；开启时才说明整理个人申请资料。

## 兼容性与错误处理

- 未提供 `usePersonalContext` 的旧客户端按 `false` 处理。
- 只有严格布尔值 `true` 才开启个人上下文，字符串或其他真值不得开启。
- 个人资料为空时，知识 RAG 仍可正常回答；开启状态下可以返回相应缺失字段提示。
- 后台任务恢复、取消和结果轮询协议保持不变。
- 学校选择、规划生成等其他产品功能不改变其已有个人资料行为。

## 测试与验收

- 服务级测试证明默认请求不会调用 planning 或 activity portfolio，也不会返回个人来源。
- 服务级测试证明开启后只包含当前画像、当前申请档案和最近更新规划，不包含历史快照或其他规划。
- HTTP/任务测试证明 `usePersonalContext` 能通过同步和后台任务边界，并且任务载荷不保存个人资料正文。
- 页面测试证明开关默认关闭、普通问题传 `false`、快捷任务自动开启并立即提交、清空对话恢复关闭状态、启发性机器人不显示开关。
- 更新原先强制要求 `student-backup` 和 `application-portfolio` 的旧测试，使其显式开启个人上下文。
- 运行 `npm run verify`。
- 在约 1280px 与 390px 宽度对申请机器人页面执行浏览器烟雾检查，确认开关、输入框和提交按钮可见可用且无布局溢出。

## 非目标

- 不删除规划中心的历史快照功能或数据。
- 不修改固定的申请规划 Agent 提示词文件。
- 不重做申请机器人页面整体视觉设计。
- 不改变启发性机器人、选校系统或规划生成器的数据策略。
