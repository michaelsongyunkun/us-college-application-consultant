# Portfolio Capability Radar Agent Design

## 1. Summary

在“我的申请档案”中加入一个专门的“档案能力评估智能体”。它只评估选校外的信息，包括成绩与考试、课外活动、竞赛、夏校/项目、推荐信准备和可证明成果，并生成能力雷达图、优势诊断、短板提醒和下一步行动建议。

该智能体不做选校推荐，不估录取概率，也不读取已保存的选校计划作为评分依据。

## 2. Contacts

- 产品负责人：Michael Song，确认评估维度、口径和页面优先级。
- 工程实现：Codex，负责前后端结构、评分规则、DeepSeek 调用、图表与测试。
- 内容/顾问角色：申请规划顾问，校准评分解释是否符合美本申请语境。

## 3. Background

当前“我的申请档案”已经沉淀了学生的成绩、活动、竞赛、夏校、推荐信和选校计划，也支持 Ask DeepSeek 做通用档案体检。但通用问答页和选校系统混在一起时，用户容易把“学生能力建设”和“选校策略/录取概率”混为一谈。

这次新增的智能体应该放在档案页内，让用户先看清自己的申请资产强弱，再决定是否补活动、补材料、补成绩或进入选校。

## 4. Objective

目标：让学生在进入选校前，快速知道自己的档案能力结构是否均衡，哪些证据最强，哪些地方会拖累整体申请叙事。

关键结果：

- 80% 的已登录用户能在“我的申请档案”一屏内找到“能力评估”入口。
- 用户点击一次后，可以看到 6-8 个维度的雷达图和文字解读。
- 评估结果明确列出“依据了哪些档案信息”和“哪些信息缺失导致置信度下降”。
- 智能体输出中不出现具体院校推荐、录取概率、冲刺/匹配/保底名单。
- 评估结果可保存，并可在后续 Word/SVG 导出中带出摘要。

## 5. Market Segments

主要用户是正在准备美本申请的学生和家长。他们已经填写了一部分档案，但不知道这些材料是否能形成有说服力的申请画像。

典型任务：

- 想知道当前档案是不是“只有活动数量，没有质量”。
- 想知道成绩、竞赛、项目、推荐信是否互相支撑。
- 想先补强自己，再进入选校。
- 想把顾问式诊断变成可复盘的图表和行动清单。

## 6. Value Propositions

- 把零散档案变成一张能力雷达图，用户一眼能看出强弱。
- 把“泛泛建议”改成基于证据的诊断，每个分数都对应档案里的具体信息。
- 把选校策略前置为能力建设，不制造录取承诺。
- 帮用户形成下一步动作：补成绩、补成果、补证明材料、补推荐信素材。

## 7. Solution

### 7.1 UX

在“我的申请档案”的完整度模块下方、分段导航上方加入一个新面板：

- 标题：档案能力评估智能体
- 主按钮：生成能力雷达图
- 辅助状态：最近一次评估时间、输入完整度、AI/规则评估状态
- 输出区域：
  - 能力雷达图
  - 总体判断
  - 3 个最强证据
  - 3 个优先短板
  - 30 天行动建议
  - 数据缺口提醒

分段导航新增“能力评估”锚点。页面不需要新增营销式介绍，入口应像工具一样安静、直接。

### 7.1.1 Frontend Visual Design

前端实现必须按 `frontend-ui-engineering` workflow 执行，目标是让它像一个成熟的申请工作台组件，而不是 AI 生成的炫技模块。

设计原则：

- 继续沿用现有申请档案页面的工作台风格，避免新的大渐变、大圆角、营销式 hero 和过重阴影。
- 雷达图是视觉中心，但不要独占整屏；桌面端采用“左侧雷达图 + 右侧诊断摘要”的两栏布局，移动端堆叠为“雷达图、总评、短板、行动”。
- 面板使用现有 `panel`、`portfolio-panel`、`status`、按钮和间距体系，新增样式只服务能力评估本身。
- 雷达图配色使用克制的多维度颜色，不让页面读成单一蓝紫色；每个维度同时显示文字标签和分数，不能只靠颜色表达强弱。
- 分数展示要有层次：总分或总体判断最醒目，单项分数次之，证据和缺失项用较轻文本。
- 按钮文案直接：主按钮为“生成能力雷达图”，次按钮可为“保存评估”“重新生成”，不增加解释型按钮。
- 空状态要明确告诉用户还缺哪些输入，而不是显示空白雷达图。
- 加载态使用轻量 skeleton 或状态文本，避免全屏 loading。
- 错误态要保留规则评分结果；如果 AI 解读失败，显示“已生成基础评分，AI 解读暂不可用”。
- 所有交互元素必须支持键盘访问，雷达图需要提供等价的文本列表供屏幕阅读器理解。

验收时至少检查 320px、768px、1024px、1440px 四个宽度，确保图表、按钮和长中文文案不会重叠或溢出。

### 7.2 Radar Dimensions

建议先用 7 个维度，分数范围为 0-100：

- 学术准备度：课程体系、GPA/IB、SAT、AP 的完整度和强度。
- 专业方向一致性：活动、竞赛、夏校方向是否能共同支持一个清晰主题。
- 活动深度：是否有长期投入、明确角色、复杂任务和持续进展。
- 成果与影响力：是否有奖项、作品、研究产出、可量化结果或外部影响。
- 主动性与领导力：是否有发起、组织、管理、协作或带动他人的证据。
- 竞争性经历：竞赛、研究、夏校或高门槛项目的挑战程度和结果。
- 材料准备度：推荐信关系、素材包、证明链接、项目说明是否准备好。

每个维度都需要显示：

- score：0-100
- confidence：high / medium / low
- evidence：引用的档案证据
- missing：影响判断的缺失字段
- nextAction：最优先的补强动作

### 7.3 Data Scope

必须纳入：

- `academicRecords`
- `activities`
- `competitions`
- `summerSchools`
- `recommendationLetters`
- 可选纳入学生基础资料中的年级、兴趣、目标专业方向，但不能从选校计划中反推目标专业。

必须排除：

- `applicationPlan`
- `schoolSelectionVersions`
- 院校百科、学校列表、选校概率、冲刺/匹配/保底分组
- 任何从已选学校推导出的强弱判断

### 7.4 Technology

推荐采用“规则评分 + AI 解读”的混合方案：

1. 前端点击生成。
2. 服务端读取当前用户档案。
3. `portfolio-capability-scorer` 先做稳定的规则评分，输出每个维度的初始分、证据和缺失项。
4. DeepSeek 只负责把规则结果转成顾问式解读和行动建议，不能凭空增加档案中不存在的证据。
5. 服务端校验 DeepSeek JSON。如果 AI 返回不合规，退回规则评分版本。
6. 前端用 SVG 画雷达图，方便后续导出 Word/SVG。

建议新增数据形态：

```json
{
  "capabilityAssessment": {
    "version": "v1",
    "generatedAt": "2026-06-09T00:00:00.000Z",
    "inputHash": "portfolio-non-school-fields",
    "overallSummary": "当前档案学术准备较完整，但成果证据和推荐信素材仍需补强。",
    "radarScores": [
      {
        "key": "academicReadiness",
        "label": "学术准备度",
        "score": 76,
        "confidence": "medium",
        "evidence": ["已填写 GPA 与 AP 记录"],
        "missing": ["SAT 最近一次考试日期"],
        "nextAction": "补齐最高分和考试时间，并标注是否计划再考。"
      }
    ],
    "strengths": [],
    "gaps": [],
    "actions30Days": []
  }
}
```

服务端可新增接口：

- `POST /api/portfolio-capability-assessment`：生成评估。
- `GET /api/my-activities`：继续返回已保存的 `capabilityAssessment`。
- `PUT /api/my-activities`：允许保存评估结果。

### 7.5 Assumptions

- 用户愿意先看能力结构，再进入选校。
- 规则评分能提供稳定底座，减少 AI 输出漂移。
- 雷达图比纯文字更适合家长和学生快速理解档案短板。
- 当前档案字段足够支撑 V1，不必马上新增大量表单字段。

## 8. Release

### V1

- 在档案页新增智能体面板和“生成能力雷达图”按钮。
- 新增规则评分函数。
- 新增 DeepSeek 专用 prompt 与服务端 JSON 校验。
- 雷达图用 SVG 渲染。
- 评估结果保存到申请档案。
- 测试覆盖“排除选校信息”和“雷达图字段完整”。

### V2

- Word/SVG 导出加入能力评估摘要。
- 支持历史评估版本，展示本次和上次分数变化。
- 行动建议可以一键写入 DeepSeek 行动清单或规划任务。

### V3

- 根据短板联动资源库、竞赛库、夏校库，但仍不直接进入选校推荐。
- 支持顾问后台查看学生能力画像。
- 支持按目标专业方向切换评分口径。

## Acceptance Tests

- 档案页出现“档案能力评估智能体”和“生成能力雷达图”。
- 生成请求不发送 `applicationPlan` 和 `schoolSelectionVersions`。
- 服务端 prompt 明确禁止输出院校推荐、录取概率和冲刺/匹配/保底名单。
- 返回的 `radarScores` 至少包含 6 个维度，每个维度都有 `score`、`confidence`、`evidence`、`missing` 和 `nextAction`。
- API key 缺失时仍能显示规则评分版本，而不是空白失败页。
- 保存后刷新页面，最近一次评估仍存在。
- Word/SVG 导出不会把该评估误标成选校或录取预测。
